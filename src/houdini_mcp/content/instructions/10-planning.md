# Planning

- Restate the goal in one sentence.
- Inspect the scene, selection, frame range, network, and errors.
- Prefer one atomic operation over a click-by-click sequence.
- Ask one focused question only when the answer changes the recipe. Batch questions.
- Work coarse to fine. Build, show, then refine.
- Cache expensive stages; a cache is a checkpoint, not a deliverable.
- Stop when the goal is met. No unrequested polish.

## Known-pipeline fast path

When the scene has a working example of the requested asset class, that example is the specification.
Read it once and build from it, changing only the inputs. Do not read help pages, parameter schemas, or
intermediate node parameters for nodes already in the template.

Do not spend a separate discovery turn on work a workflow guide already specifies.
Resolve the inputs, build, and verify in one turn.

For repeated work, use the workflow's spec table or batch build instead of rediscovering each asset.
